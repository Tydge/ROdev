## 已实现

- 共享 `trade_prices.json`，买卖双方使用相同 nameID 固定单价；未标价或分类器 KEEP 的物品不自动出售。
- 依据真实 binID 选择物品；nameID、鉴定、精炼、插卡、随机属性、grade 构成身份指纹。
- nameID / binID 确定排序，每批最多 10 项；堆叠按实际数量计价，多件同 ID 装备不合并。
- 分段 nonce 私聊清单，精确白名单和可见角色距离检查；实际付款依据服务端逐条报价。
- 每次只发一条加物请求，服务端 ACK 后才发下一项。
- 商人支付前与锁定前重新检查人物余额、空格、重量、Cart 空格/重量/堆叠限制。
- Cart 预留背包里尚未搬入车的已标价库存，避免连续批次超收；不执行自动搬运。
- 实际报价不匹配、额外物品/钱、数量异常、属性改变、距离/忙碌变化均取消。
- 锁定和最终提交分开；双方服务端锁定回显齐全才提交，每笔只提交一次。
- 完成事件后核对真实 Zeny 更新及 Inventory/Cart 快照，卖家还等待买家 VERIFIED 才继续下一批。
- 超时真实取消，并等待服务端取消与资产回滚；不能核对时停在 halted，不重放付款。
- 掉线后可用 `economy trade reconcile` 显式核对新资产并重建，插件不修改资产。
- 活动会话不允许用 reset 丢弃，卸载会发送取消，普通 Trade 启用期间停止收购店自动开店。

## 协议依据与关键接线

核对了本地 `rathena/src/map/trade.cpp`、`clif.cpp` 和 OpenKore `Network/Receive.pm`：

1. 原生 `currentDeal{other}` 按 nameID 合并，不能用于区分同 ID 装备；新实现读取 `packet/deal_add_other` 原始条目。
2. 原生 `deal_add_you` 使用单个 `lastItemAmount` 并立即从本地库存减去物品；因此逐项 ACK 串行发送，并保留成交前快照。
3. `trade_tradeaddzeny` 只向对端发送报价；付款方没有独立“加钱 ACK”。买家先报价，等卖家核价锁定后再锁定。
4. 原生锁定会预扣本地 Zeny，不能单凭 `$char->{zeny}` 当成实际付款；核对要求交易开始后的真实 `zeny_change`。
5. `Misc::sendMessage` 默认按 80 字符拆分，会截断清单指纹；新协议通过 `Misc::sendMessage_send` 单帧调用原生 `sendPrivateMsg`，同时保留私聊审计上下文，并独立限制长度和发送频率。
6. 活动交易取消必须发 `sendCurrentDealCancel`；`sendDealReply(4)` 仅适用于请求阶段。

## 配置与边界

- 双方升级到同一新协议后使用，旧 `economy_trade_item / economy_trade_price` 不再生效。
- 默认固定单价：4001/4004/4031/4021/4023=10,000，4051=20,000，1208=3,000，2102=5,000。实机按现有真实掉落增加 Poring / Drops / Peco Peco Card 三种卡片，仍使用固定 10,000z 单价。
- 人物槽位按保守 100 槽计算，每个来货条目预留一个槽；已扩容或可合并的库存可能被提前拒绝。
- Weight 按服务端单位换算，另留 1 显示单位，避免 OpenKore 向下取整低估重量。
- 包含精炼、插卡、随机属性的库存可以保持独立身份；若当前 OpenKore 无法完整保留某属性，指纹或快照不匹配则拒绝/暂停，不降级按 nameID 成交。
- bot07 仍是静止探针，默认 autoGear 关闭，装备不会绕过评估自动出售。
- world_ai 自动执行开启或忙碌的角色不启动交易；固定点寻路、回城控制权、卖家队列属于阶段 7–8。

## 实测发现并修复

1. 直接调用发送器虽然能送达私聊，但缺失 `lastpm` 上下文使发送日志显示空收件人。
   改用不拆分文本的 `Misc::sendMessage_send`，同时保留完整协议帧和可读审计日志。
2. `economy_trade_enabled=0` 先 abort 再 tick，idle 状态仍可能发起新交易。
   现在启动/接单的 safe 条件也检查开关，离线接线测试覆盖此边界。
3. 关闭开关或卸载已 VERIFIED 的 done 会话不应转为 rollback。
   done 不再取消；已验证成交后正常重登会清理已完成会话，不误停在 halted。

上述修复已重新跑完整 7 组回归，且最终实机重试及重登采用修复后的代码。
